# Конвейер на GPU

**Дата:** 7 октября 2026 · RTX 2070 Max-Q (8 ГБ), torch 2.14.1+cu130, ffmpeg с NVDEC/NVENC.

## Что было и что стало (один файл GoPro 1080p, 95 с прыжка)

| этап | было (CPU) | стало |
|---|---|---|
| старые эвристики раскрытия/дрога | 32 с | 0 — запускаются, только если модель фаз не нашла границу |
| загрузка DINOv2 | 28 с | 1 с + 7 с импорт torch, раз на процесс — модель в TorchScript, без `import transformers` (23 с) |
| модель фаз: эмбеддинги + уточнение exit | 26 с | 3–7 с |
| анализ свободного падения (2 кадр/с) | 42 с | 11–20 с (рамки людей на GPU; лица MediaPipe на CPU — теперь основная часть) |
| **префилл одного файла (`segment_file`)** | **~70 с** | **~7 с (медиана на 70 файлах)** |

## Как ускорено

- **`tandem/video_io.py`** — кадры без временных JPEG: ffmpeg → pipe → массивы.
  Декодирование на NVDEC, масштабирование `scale_cuda` (10-бит DJI → 8 бит там же),
  откат на CPU, если GPU не справился. Время каждого кадра — от самого ffmpeg (`showinfo`).
  Файлы с меткой поворота (камера вверх ногами, вертикальные): NVDEC пропускает
  автоповорот ffmpeg, поэтому поворот применяется после выгрузки кадра — без этого
  13 из 50 файлов `св. падение` шли перевёрнутыми и модель ошибалась.
- **Только ключевые кадры для 1 кадр/с.** У всех камер архива ключевой кадр ровно раз в
  секунду: `-skip_frame nokey` декодирует 1/50–1/60 потока (4K HEVC: 4 с вместо 21 с).
  Модель фаз училась на кадрах ffmpeg-фильтра `fps`, где содержимое на ~0.5 с позже
  метки времени; ключевой кадр она читает как слот на 0.5 с раньше (`KEYFRAME_SHIFT_S`).
- **DINOv2 на GPU в fp16**, батчами из массивов (`probe.embed_arrays`); TorchScript
  совпадает с исходной моделью (косинус 1.0000).
- **Рамки людей** в анализе падения — RT-DETR на GPU в fp16 (он же был учителем для доли
  пары); MediaPipe-детектор остаётся запасным на CPU. RT-DETR находит пару там, где
  MediaPipe её теряет (тёмные костюмы на ярких облаках).
- **Монтаж** — NVDEC + `scale_cuda` + NVENC.

## Точность не потеряна

70 размеченных прыжков `E:\V\Sep\св. падение` и `E:\V\10` — модель на них не обучалась;
«старый» — черновики прежнего CPU-конвейера. Честное сравнение на 67 (без 3 файлов,
которые старый конвейер не находил и черновики которых достраивались вручную), метки,
поставленные человеком, доля в пределах 1 с / 2 с:

| граница | старый CPU | GPU, старая выборка (`fps`) | **GPU, ключевые кадры −0.5 с** | ключевые без сдвига |
|---|---|---|---|---|
| exit (n=6) | 50/50 % | 50/67 % | 67/83 % | 67/83 % |
| drogue (n=19) | 74/89 % | 74/89 % | **74/100 %** | 63/89 % |
| deploy (n=60) | 82/100 % | 78/97 % | **85/95 %** | 32/95 % |
| breakoff (n=22) | 73/95 % | 73/91 % | **77/95 %** | 77/86 % |

По умолчанию — ключевые кадры со сдвигом (`KEYFRAMES_1FPS = True`); `False` возвращает
старую выборку (декодирует всё окно, медленнее).

## Ограничения

- `import torch` ~7 с на процесс — пакетные прогоны держат модели в одном процессе.
- RT-DETR грузится через transformers (~25 с импорт, раз на процесс) — только анализ падения.
- Телеметрия DJI (разбор protobuf на Python) — до 5–6 с на файл; следующий кандидат.
