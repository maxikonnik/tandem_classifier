# Разбор телеметрии GPMF из GoPro HERO11

Парсер метаданных GoPro и автоматическая разметка фаз прыжка по потокам
камеры (без GPS — в этих съёмках фикс GPS есть только на земле).

## Файлы

| Файл | Назначение |
|---|---|
| `gpmf_full.py` | Парсер GPMF: KLV, вложенность, `SCAL`, `TYPE`, комплексные структуры |
| `analyze.py` | Агрегация потоков в посекундные признаки |
| `phases.py` | Сегментация: самолёт / свободное падение / раскрытие / под куполом |
| `batch.py` | Прогон по всей папке `Samples` и сводная статистика по фазам |

## Использование

```bash
python3 phases.py "Samples/16 03 24 Затяжной прыжок (Дмитрий)/GX010015.MP4"
python3 batch.py
```

Требуется `ffmpeg`/`ffprobe` (извлечение трека `gpmd`) и `numpy`.

## Как определяются фазы

* **Выход** — первая секунда, с которой 4 секунды подряд держатся `ISO <= 110`
  и выдержка короче 1/1800. Переход из полумрака салона на дневной свет
  камера отрабатывает за доли секунды, поэтому граница очень резкая.
* **Раскрытие** — максимум `0.6 * g_max + 1.4 * g_mean` в окне, начинающемся
  через 8 с после выхода (отступ нужен, чтобы не поймать отделение).
* Остальное делится этими двумя границами.

Проверено на 26 файлах длиннее 80 с: сегментация отработала на 22, длительность
свободного падения 44–62 с в большинстве прыжков.

## Замечания по потокам HERO11

* `FACE` — `TYPE = "BBSSSSSBB"`, 14 байт: `ver, confidence%, ID(16 бит),
  x, y, w, h, smile%, blink%`. Координаты нормируются `SCAL = 65535`.
  При `confidence < 50` поля `smile`/`blink` заполнены мусором.
* `TMPC` лежит внутри `STRM` акселерометра и НЕ масштабируется `SCAL`
  этого потока — это готовый float в °C.
* `UNIF` на HERO11 всегда 0 — поток мёртвый, использовать нельзя.
* `HUES` — `TYPE = "BB"`, три пары (hue, weight); угол = `hue * 360 / 255`.
* `GPS9` присутствует в 82 файлах из 157, но фикс (`GPSF >= 2`) есть только
  в 11 и только у земли.
